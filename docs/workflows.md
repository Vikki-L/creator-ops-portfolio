# 端到端流程与交接

[返回项目首页](../README.md) · [系统总览](system-overview.md)

本页把旧模块串起来，列出每一环的交接内容。它是基于公开案例的业务梳理，不替代正式状态机或接口文档。

| 环节 | 输入 | 交给下一环的内容 | 责任人 / 异常处理 |
|---|---|---|---|
| 1. 身份确认与入职 | 通过招募的候选人、入职邀请 | 已识别的 Creator、归属、入职进度 | C1；邀请码无效或身份不明交 Onboarding 团队 |
| 2. 内容提交与入库 | 视频或已发布链接、平台、模板信息 | 可追踪的投稿记录 | B6；缺信息、重复或解析失败需有补充入口 |
| 3. AI 辅助判断 | 投稿、规则与模板参照 | AI 建议、理由、需复核的问题 | A3；材料不足时不能把推测当成观察事实 |
| 4. Coach 复核与反馈 | 投稿记录、AI 建议、历史反馈 | 人工审核结论、Creator 可读的反馈 | A1；保留修改与复核历史，分清不同版本 |
| 5. 数据追踪 | 平台内容记录与采集结果 | 带更新时间和时间范围的数据 | B1 / B4；缺数与真实零值应区分 |
| 6. 生成周期明细 | 对应周期的视频、规则、奖励与调整项 | 可核对的应付明细 | A2；调整需理由，异议处理后应重新对应确认版本 |
| 7. Creator 确认 | A6 展示的同一份明细 | 确认结果或异议 | Creator + Coach；未确认项作为待处理事项跟进 |
| 8. 导出与支付核对 | 已满足业务条件的结算明细 | 支付批次、逐笔结果与历史记录 | A2 + 财务；导出成功和支付成功分别记录 |
| 9. 下一轮指导 | 视频表现、模板表现、周期评分 | 需要指导、观察或管理复核的事项 | B1 / B3 + Coach；评分辅助决策，不能直接替代人的判断 |

投稿可能是已发布内容的链接。现有材料不足以把所有内容统一描述成先审、再由系统代发。

## 三个容易断开的交接

**投稿到审核**：需要沿用同一条视频记录。Bot 解析成功不代表审核完成；链接补充或修改后，要能找到原投稿和已有反馈。

**审核到结算**：需要说明哪些内容符合该周期规则、为什么计入。播放表现、审核结果和结算资格是不同信息，不能用一个通过字段同时表示。

**确认到支付**：Creator 看到并确认的是哪一版明细，财务导出的是哪个批次，实际成功的是哪些记录，需要能互相对应。支付失败不应通过重新导出整批来掩盖。

## 已有材料与后续需核对的内容

旧案例对主流程有说明，但公开资料还不足以还原完整状态机。继续开发前，应从原始 PRD 核对：投稿版本和去重、审核修改轮次、结算资格、明细确认版本、超期和争议处理、支付失败与跨期补结、权限及操作留痕。

以上是待核对项，不是本次整理新增并上线的功能。
